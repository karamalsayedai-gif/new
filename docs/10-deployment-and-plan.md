# 10. التثبيت والتوزيع + خطة التنفيذ + هيكل المشروع

## 10.1 متطلبات التثبيت والتوزيع

### متطلبات جهاز المعرض (الدنيا الموصى بها)
- Windows 10/11 64-bit، معالج ثنائي النواة، **8GB RAM** (يعمل على 4GB)، قرص SSD يفضَّل، مساحة حرة ≥ 10GB (للبيانات والنسخ).
- شاشة 1366×768 كحد أدنى (التصميم يستهدف 1920×1080).
- طابعة حرارية 80مم معرَّفة على ويندوز + طابعة A4، قارئ باركود USB اختياري (وضع لوحة مفاتيح).
- **UPS موصى به بشدة** (يحمي الجهاز والقاعدة من الانقطاعات).
- لا حاجة لإنترنت إطلاقًا للتشغيل.

### حزمة التوزيع (Installer)
- **Inno Setup** (للخيارين ‎.NET وFlutter): ملف EXE واحد يُنقل على فلاشة.
- يقوم بـ: نسخ التطبيق إلى Program Files، إنشاء ProgramData\MotoPOS بهيكل المجلدات (وثيقة 02 §2.5)، اختصار سطح مكتب + بدء تلقائي اختياري، تسجيل إلغاء التثبيت (لا يحذف البيانات أبدًا — رسالة صريحة).
- ‎.NET: نشر Self-contained أحادي الملف (لا يتطلب تثبيت Runtime). Flutter: مجلد التطبيق + مكتبات VC++ إن لزمت (يضمّنها الـ Installer).
- توقيع الكود Code Signing موصى به لتفادي تحذيرات SmartScreen ومضادات الفيروسات (سؤال Q7 — له تكلفة سنوية).

### أول تشغيل (First-Run Wizard)
1. إنشاء قاعدة البيانات وتشغيل كل الـ Migrations.
2. إنشاء حساب Owner (إجباري بكلمة مرور).
3. بيانات المعرض + الشعار + إعدادات الطباعة (اختبار طباعة تجريبية لكل طابعة).
4. طرق الدفع وأرصدتها الافتتاحية.
5. (اختياري) الأرصدة الافتتاحية: وحدات/أصناف/عملاء/موردون — أو تخطٍّ والإدخال لاحقًا من S16.

### الترقيات اللاحقة
- Installer جديد على فلاشة يُثبَّت فوق القديم؛ عند أول تشغيل: نسخة `pre_migration` تلقائية ثم ترقية المخطط داخل معاملة. البيانات لا تُمس.
- التطبيق يرفض العمل مع قاعدة أحدث من إصداره (رسالة واضحة).

### الصيانة عن بُعد (بدون إنترنت دائم)
- زر «حزمة دعم فني»: يضغط logs + manifest بلا بيانات عملاء حساسة في ملف واحد يُرسل للمطور.
- الاستعادة من نسخة، وأداة فحص/إصلاح (`integrity_check`, reindex) داخل شاشة النسخ الاحتياطي.

## 10.2 خطة التنفيذ على مراحل

> المطلوب أن يشمل الإصدار الأول كل النطاق؛ لذلك هذه **مراحل بناء داخلية** تنتهي كلها قبل تسليم المعرض، وكل مرحلة تُختبر وتُجمَّد قبل التالية. التقديرات بافتراض مطور رئيسي واحد متفرغ (تُقسم على اثنين بتوازٍ جزئي).

| المرحلة | المحتوى | المخرَج القابل للاختبار | تقدير |
|---|---|---|---|
| **M0 — الأساس** | هيكل المشروع، SQLite + Migrations + PRAGMAs، Repositories، المستخدمون والأدوار والصلاحيات، تسجيل الدخول وقفل الخمول، audit_log، الإعدادات، إطار الشاشة الرئيسية + Dark/Light | دخول بأدوار مختلفة وقوائم تظهر حسب الصلاحية | 3 أسابيع |
| **M1 — الكتالوج والمخزون** | ماركات/موديلات/ألوان/تصنيفات، الوحدات (CRUD + آلة الحالة + الحركات)، الأصناف الكمية، الرصيد الافتتاحي، البحث، تنبيهات المخزون والركود | إدخال وحدات والبحث بالشاسيه وسجل حركة يعمل | 3 أسابيع |
| **M2 — الأطراف والمالية الأساسية** | عملاء/ضامنون/موردون/مندوبون، طرق الدفع، سندات القبض/الصرف، المصروفات وفئاتها، finance/party transactions، كشوف الحساب | سند قبض/صرف يحرك رصيد طريقة دفع وكشف حساب صحيح | 3 أسابيع |
| **M3 — المشتريات** | فاتورة الشراء متعددة الوحدات، مصاريف الشراء وتوزيعها، مرتجع الشراء، كشف حساب المورد | شراء 3 وحدات بمصاريف موزعة وتظهر تكلفتها صحيحة | 2 أسابيع |
| **M4 — الورديات والخزنة** | فتح/قفل، الجرد والمطابقة والفروق، تقرير Z، ربط السندات بالوردية | يوم عمل كامل محاكى بوردية مطابقة | 2 أسابيع |
| **M5 — البيع وPOS** | شاشة POS، نقدي/آجل، خصومات وموافقات، ضريبة، حجز وعربون، استبدال مستعمل، مرتجع بيع، الطباعة (ريسيت + A4) | بيع كامل بكل السيناريوهات مع طباعة فعلية | 4 أسابيع |
| **M6 — التقسيط** | العقد والجدولة، التحصيل الكلي/الجزئي/المتعدد، السداد المبكر، المتأخرات والتنبيهات، عقد وجدول أقساط وإيصالات مطبوعة | عقد 12 شهرًا بكل حالات التحصيل واختبارات التقريب خضراء | 3 أسابيع |
| **M7 — التقارير وDashboard** | الـ 18 تقريرًا + لوحة التحكم + تصدير PDF/Excel | كل تقرير مطابق يدويًا لبيانات اختبار معلومة | 3 أسابيع |
| **M8 — النسخ الاحتياطي والتوزيع** | يدوي/تلقائي/مجدول/فلاشة، الاستعادة بالمعالج، فحص السلامة، Installer + معالج أول تشغيل + دليل مستخدم مصور مختصر | تثبيت نظيف على جهاز آخر + استعادة نسخة كاملة | 2 أسابيع |
| **M9 — تقسية وقبول** | اختبار قبول شامل بسيناريوهات المعرض الحقيقية، ضبط أداء، مراجعة أمنية (صلاحيات/حقن SQL/تخزين كلمات المرور)، تجربة تشغيل موازٍ أسبوع في المعرض | إطلاق | 2 أسابيع |

**الإجمالي التقديري: ~27 أسبوع عمل** (± 20%). أطول مساران حرجان: M5 وM6 — وهما اللذان يجب ألا يُضغطا.

**قواعد جودة إلزامية طوال المراحل:** اختبارات وحدات لكل حساب مالي (فاتورة/أقساط/توزيع/متوسط تكلفة)، وبيانات Seed تجريبية قابلة للتحميل، وكل مرحلة تنتهي بمراجعة كود + نسخة موسومة (git tag).

## 10.3 هيكل المشروع المقترح

### الخيار الأول: ‎.NET 8 WPF
```
MotoPos/
├── src/
│   ├── MotoPos.Domain/            # الكيانات + آلات الحالة + قواعد العمل (بلا أي مرجع UI/DB)
│   ├── MotoPos.Application/       # الخدمات/Use-Cases + واجهات Repositories + DTOs + Validators
│   ├── MotoPos.Infrastructure/    # SQLite (Microsoft.Data.Sqlite) + Repositories + Migrations/
│   │   └── Migrations/0001_init.sql … (مرقمة، تُطبق بالترتيب داخل معاملة)
│   ├── MotoPos.Printing/          # قوالب المستندات (QuestPDF) + ESC/POS + إدارة الطابعات
│   └── MotoPos.Desktop/           # WPF: Views/ ViewModels/ Themes(Dark,Light)/ Resources.ar.resx
├── tests/
│   ├── MotoPos.Domain.Tests/      # حسابات الفواتير والأقساط والتقريب (الأهم)
│   └── MotoPos.Application.Tests/ # سيناريوهات Use-Cases على SQLite in-memory
├── installer/ MotoPos.iss         # Inno Setup
├── docs/                          # هذه الوثائق
└── tools/seed/                    # بيانات تجريبية
```

### الخيار الثاني: Flutter Desktop (لو حُسم Q1 لصالحه)
```
motopos/
├── lib/
│   ├── domain/        # entities + state machines + قواعد (Dart خالص قابل للاختبار)
│   ├── application/   # services/use-cases + validators
│   ├── data/          # drift (أو sqflite_common_ffi) + migrations + repositories
│   ├── printing/      # pdf + printing + esc_pos
│   ├── ui/            # screens/ widgets/ theme/ (Dark/Light) — RTL
│   └── main.dart
├── test/              # نفس فلسفة الاختبارات
├── installer/ inno.iss
└── docs/
```
- في كلا الخيارين: **الفصل الصارم Domain/Application عن UI وDB هو ما يسمح لاحقًا بالانتقال إلى PostgreSQL أو إضافة واجهة ويب دون إعادة كتابة.**

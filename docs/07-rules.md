# 7. قواعد التحقق وقواعد العمل

## A. Validation Rules (قواعد التحقق — على مستوى الإدخال)

> تُطبق في طبقتين: فوري في الواجهة (رسالة تحت الحقل) + نهائي في طبقة الخدمات قبل المعاملة (المصدر الموثوق). قاعدة البيانات خط دفاع ثالث بـ CHECK/UNIQUE.

### V-1 عام (كل المستندات)
- التاريخ لا يكون مستقبليًا (سماحية يوم واحد بإعداد)، ولا أقدم من تاريخ آخر إقفال سنة (لاحقًا).
- كل مبلغ ≥ 0 وبالقرش؛ الكمية عدد صحيح > 0.
- لا حفظ مستند بلا بند واحد على الأقل، ولا بند بقيمة سالبة.
- المستند بعد الحفظ (Posted) لا يقبل تعديلًا ماليًا — فقط إلغاء/مرتجع حسب الصلاحية.

### V-2 الوحدات والأصناف
- الشاسيه والموتور: إلزاميان، فريدان (غير حساسين لحالة الأحرف)، طول 5–30 حرف/رقم، مسموح أحرف لاتينية وأرقام وشرطة. **تحذير غير مانع** لو الطول غير معتاد (لأن الأنساق تختلف بين المصانع).
- تفرد الشاسيه يُفحص ضد كل الوحدات غير الملغاة، ويُستثنى المُرتجع للمورد (يجوز رجوع نفس الشاسيه لاحقًا بشراء جديد — يُنشأ صف جديد بسجل جديد).
- سعر البيع المعلن ≥ 0، وتحذير (غير مانع، يسجل) لو أقل من التكلفة الإجمالية.
- الصنف العام: اسم إلزامي، باركود فريد إن وُجد، حد إعادة الطلب ≥ 0.

### V-3 العملاء والضامنون
- الاسم إلزامي ≥ 3 أحرف؛ الموبايل إلزامي بنمط مصري `01[0125]xxxxxxxx` (تحذير غير مانع لغيره لدعم أرقام غير مصرية).
- الرقم القومي: 14 رقمًا مع تحقق بنيوي (قرن/تاريخ ميلاد صالح)، **فريد**، إلزامي عند: بيع وحدة موتوسيكل، أي بيع آجل/تقسيط، وللضامن دائمًا.
- الضامن لا يكون هو نفسه عميل العقد (مقارنة بالرقم القومي).

### V-4 الشراء
- المورد إلزامي؛ تكلفة كل بند > 0؛ المدفوع الآن بين 0 والإجمالي.
- مصاريف الفاتورة ≥ 0 ولا يمكن توزيعها إلا على بنود وحدات/أصناف موجودة.
- مرتجع الشراء: البنود من الفاتورة الأصل فقط، الوحدة ليست `sold/reserved`، كمية الصنف المرتجعة ≤ المشتراة ناقص المرتجع سابقًا.

### V-5 البيع وPOS
- وحدة تُباع فقط إن كانت `in_stock`، أو `reserved` **لنفس العميل** (تحويل الحجز).
- بيع صنف كمي: الكمية ≤ المتاح (خيار إعداد «السماح بالسالب» مغلق افتراضيًا).
- خصم البند/الفاتورة: النسبة ≤ 100%، والمبلغ ≤ قيمة ما يُخصم منه، ومجموع الخصومات لا يجعل الصافي سالبًا.
- تجاوز حد الخصم للدور، أو تعديل سعر وحدة عن المعلن، أو بيع بأقل من التكلفة ⇒ يستوجب Approval مسجلًا (المصفوفة 03 §3.3).
- الآجل/التقسيط: عميل كامل البيانات (رقم قومي + عنوان) إلزامي؛ المدفوع < الإجمالي وإلا فهو نقدي.
- الدفع متعدد الطرق: مجموع التوزيعات = المطلوب بالضبط للبيع النقدي؛ سند الكاش يتطلب وردية مفتوحة.

### V-6 الحجز والعربون
- الوحدة `in_stock` فقط؛ العربون > 0 و≤ سعر الوحدة؛ مدة الحجز 1–90 يومًا.
- لا يجوز حجزان نشطان لنفس الوحدة (يضمنه تغير الحالة داخل المعاملة).

### V-7 التقسيط
- المقدم ≥ الحد الأدنى المضبوط (نسبة من السعر، افتراضي 0 قابل للضبط) و< الإجمالي.
- عدد الشهور 1–120؛ نسبة الفائدة 0%–100%؛ يوم الاستحقاق 1–28 (لتفادي مشاكل نهاية الشهر).
- تاريخ أول قسط > تاريخ الفاتورة وبما لا يتجاوز 3 شهور (تحذير فوق شهر).
- الضامن إلزامي حسب الإعداد (افتراضي: إلزامي فوق مبلغ تمويل معين).
- التحصيل: المبلغ > 0 و≤ إجمالي المتبقي على العقد؛ لا تحصيل على عقد `cancelled/completed`.

### V-8 المالية والوردية
- سند الصرف كاش لا يتجاوز الرصيد المتوقع الحالي بالدرج (تحذير قابل للتجاوز بموافقة، لأن العد الفعلي قد يختلف).
- التحويل بين طريقتين: المبلغ ≤ رصيد الطريقة المصدر.
- قفل الوردية يتطلب إدخال `counted_cash`، وأي فرق ≠ 0 يتطلب سببًا واعتماد Manager+.
- لا فتح وردية وأخرى مفتوحة؛ لا قبض/صرف كاش بلا وردية مفتوحة.

### V-9 المستخدمون والنظام
- كلمة المرور ≥ 6 خانات (قابل للرفع)، وتغيير إلزامي أول دخول للحسابات المنشأة.
- 5 محاولات دخول فاشلة ⇒ تجميد 5 دقائق + تسجيل في audit.
- لا تعطيل آخر مستخدم Owner نشط، ولا يعدل مستخدم صلاحيات نفسه.

## B. Business Rules (قواعد العمل)

### B-1 آلات الحالة (State Machines)

**الوحدة (vehicles.status):**
```
in_stock ──حجز──▶ reserved ──تحويل──▶ sold
   │                  │ إلغاء/انتهاء
   │                  ▼
   │◀────────────  in_stock
   ├──بيع مباشر──▶ sold ──مرتجع بيع──▶ in_stock (مع قرار الحالة جديد/مستعمل)
   └──مرتجع شراء─▶ returned_to_supplier (نهائية)
```
أي انتقال خارج هذه الأسهم مرفوض على مستوى الخدمة، وكل انتقال يسجل `vehicle_movements`.

**الفاتورة:** `posted → cancelled` فقط (لا حذف). شروط الإلغاء: لا مرتجع عليها، لا تحصيلات (أو تُعكس بسند صرف ضمن نفس معاملة الإلغاء)، وحداتها تعود `in_stock`، ولو عليها عقد تقسيط فمساره فسخ عقد (E7 بالوثيقة 09).

**القسط:** `pending → partial → paid` أو `→ waived` (سداد مبكر/إعفاء معتمد). **العقد:** `active → completed | early_settled | cancelled | defaulted` (defaulted علامة تشغيلية يضعها المدير، لا تمنع التحصيل).

### B-2 التكلفة والربح
1. تكلفة الوحدة = سعر الشراء/التقييم + كل `vehicle_costs` (نقل، تجهيز، سمسرة، نصيبها من مصاريف فاتورة الشراء).
2. عند البيع تُلتقط `cost_snapshot` في بند الفاتورة ⇒ **الربح تاريخي ثابت** لا يتغير لو عُدلت تكلفة لاحقًا (تعديل تكلفة وحدة مباعة ممنوع أصلًا إلا بقيد جرد معتمد).
3. ربح الفاتورة = Σ(سعر بيع البند بعد خصوماته) − Σ(cost_snapshot) − نصيبها من الخصم العام + المصاريف المحمّلة على العميل. **فائدة التقسيط تُعرض بندًا منفصلًا في تقارير الربح** (ربح تجاري + عائد تمويل) ولا تُخلط بربح الوحدة.
4. الأصناف الكمية: التكلفة بالمتوسط المتحرك، تُحدَّث عند كل شراء: `متوسط جديد = (رصيد×متوسط + كمية×تكلفة) ÷ (رصيد+كمية)`.

### B-3 حساب الفاتورة (ترتيب إلزامي)
```
لكل بند: صافي البند = qty × unit_price − خصم البند
subtotal = Σ صافي البنود
discount_amount = خصم الفاتورة (نسبة تُحسب من subtotal، أو مبلغ)
taxable = subtotal − discount_amount + الرسوم الخاضعة
tax = taxable × tax_rate  (تقريب نصف لأعلى لأقرب قرش)
grand_total = taxable + tax + الرسوم غير الخاضعة
المطلوب سداده = grand_total − tradein_credit − عربون الحجز المحوّل
```
لقطة `tax_rate_bp` تُخزن في الفاتورة: تغيير الإعداد لاحقًا لا يمس فواتير قديمة.

### B-4 جدول الأقساط (الخوارزمية المرجعية)
```
principal = المطلوب سداده − down_payment
interest  = round(principal × rate)
total     = principal + interest
base      = floor(total / months / 100) × 100      // قسط مقرب لأقرب جنيه
الأقساط 1..n-1 = base
القسط n        = total − base × (n−1)               // يمتص فرق التقريب
تاريخ القسط k  = first_due_date ثم نفس اليوم الثابت شهريًا (يوم 1–28 دائمًا صالح)
```
اختبارات إلزامية: Σ الأقساط = total بالضبط في كل الحالات (شهور=1، مبالغ لا تقبل القسمة، فائدة صفر).

### B-5 توزيع التحصيل
أي مبلغ محصَّل يوزَّع: الأقساط المتأخرة الأقدم أولًا → المستحق الحالي → (لو تبقى) دفعة مقدمة على القسط التالي. لا يُسمح بتخطي قسط متأخر لدفع أحدث إلا بموافقة Manager+ (تُسجل).

### B-6 العربون والحجز
- العربون إيراد معلّق (Liability) وليس مبيعات حتى يُحسم مصيره: خصم من فاتورة / رد / مصادرة (تتحول إيرادًا بسند مستقل معتمد).
- انتهاء الحجز لا يُنفَّذ آليًا؛ يولد تنبيهًا وقرارًا بشريًا مسجلًا.

### B-7 الرقابة
- لا حذف لأي مستند Posted نهائيًا (لا يوجد زر ولا SQL path في التطبيق).
- كل إلغاء يتطلب سببًا نصيًا ويُطبع على المستند «ملغاة» عند إعادة طباعته.
- الموافقات دائمًا بهوية المعتمِد نفسه (كلمة مروره)، ولا تُقبل موافقة مسبقة عامة.
- رجوع ساعة الجهاز عن آخر حركة مسجلة ⇒ تحذير + قيد audit، ويُستخدم آخر وقت معروف + ثانية للترتيب.

### B-8 الترقيم والسنة
تسلسل مستقل لكل نوع مستند داخل كل سنة ميلادية (INV/PUR/RSV/PLN/RCV/PAY/EXP/SRT/PRT/SH). التصفير سنوي افتراضيًا (إعداد).

### B-9 التنبيهات (قواعد التوليد)
| التنبيه | القاعدة الافتراضية (قابلة للضبط) |
|---|---|
| قسط مستحق اليوم | due_date = اليوم وحالته pending/partial |
| قسط متأخر | due_date < اليوم — تصعيد اللون بعد 7 و30 يومًا |
| مخزون منخفض | qty_on_hand ≤ low_stock_threshold |
| وحدة راكدة | in_stock منذ ≥ 90 يومًا |
| حجز يوشك على الانتهاء | expires_at − اليوم ≤ 1 |
| نسخ احتياطي | فشل آخر نسخة، أو مضى > 26 ساعة بلا نسخة يومية |

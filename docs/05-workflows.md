# 5. مسارات العمل التفصيلية (Workflows)

> كل مسار موصوف بالخطوات + ما يحدث في قاعدة البيانات داخل **معاملة واحدة ذرّية** + المطبوعات الناتجة. رموز الجداول تشير للوثيقة 04.

## WF-01: الشراء من مورد

**المشغّل:** وصول موتوسيكلات/بضاعة من مورد. **الصلاحية:** Manager+

1. شاشة «فاتورة شراء جديدة»: اختيار المورد (أو إضافته فورًا)، تاريخ الفاتورة، نوع السداد (نقدي/آجل/جزئي).
2. إضافة البنود:
   - **وحدة موتوسيكل:** موديل، لون، سنة، شاسيه، موتور، حالة (جديد/مستعمل)، تكلفة الوحدة، سعر بيع مقترح. النظام يرفض شاسيه/موتور مكررًا فورًا أثناء الكتابة.
   - **صنف عام:** الصنف + الكمية + تكلفة الوحدة.
3. إضافة مصاريف الفاتورة (نقل، سمسرة…) واختيار أسلوب التوزيع: بنسبة القيمة (افتراضي) / بالتساوي / بدون توزيع.
4. تسجيل المدفوع الآن (0 حتى الإجمالي) وطريقة الدفع.
5. **الحفظ (معاملة واحدة):**
   - إدراج `purchase_invoices` + `purchase_invoice_items` + `purchase_expenses`.
   - إنشاء صف `vehicles` لكل وحدة بحالة `in_stock` مع `base_cost` + توزيع المصاريف في `vehicle_costs` وتحديث `total_cost`.
   - `vehicle_movements(purchased)` لكل وحدة + `stock_movements(purchase)` للأصناف وتحديث `qty_on_hand` وتكلفة المتوسط المتحرك.
   - `party_transactions` على المورد بقيمة الفاتورة (دائن) وبالمدفوع (مدين) وتحديث رصيده.
   - لو دُفع مبلغ: `vouchers(payment)` + `finance_transactions(out)` وخصم من رصيد طريقة الدفع (سند الكاش يتطلب وردية مفتوحة).
   - `audit_log(create)`.
6. **المطبوعات:** إذن استلام/سند صرف عند الدفع.

**قواعد رئيسية:** لا حفظ بدون بند واحد على الأقل؛ التكلفة > 0؛ المدفوع ≤ الإجمالي؛ الفاتورة بعد الحفظ لا تُعدَّل ماليًا — التصحيح بمرتجع أو إلغاء (بشرط ألا تكون أي وحدة منها بيعت أو حُجزت).

## WF-02: إدخال المخزون (رصيد افتتاحي + ضبط)

- **رصيد افتتاحي** (أول تشغيل): شاشة استيراد/إدخال وحدات موجودة فعلًا بدون فاتورة شراء: تُنشأ `vehicles` بحركة `opening_balance` بتكلفة تقديرية، وكذلك أرصدة الأصناف والعملاء والموردين وطرق الدفع الافتتاحية.
- **الجرد الدوري:** إنشاء `stocktakes` → طباعة كشف عدّ → إدخال المعدود → شاشة الفروق (وحدة مسجلة غير موجودة/موجودة غير مسجلة، فرق كمية صنف) → اعتماد Manager+ → قيود تسوية `stocktake_adjust` مسجلة بالسبب.
- **تحويل حالة وحدة (جديد ↔ مستعمل):** من بطاقة الوحدة، بصلاحية Manager+، تُسجل `vehicle_movements(condition_changed)` بالسبب.

## WF-03: البيع النقدي (POS)

**المشغّل:** عميل يشتري ويدفع بالكامل. **الصلاحية:** Cashier+ (بشرط وردية مفتوحة لأي قبض كاش)

1. شاشة POS: بحث فوري (شاسيه/موتور/موديل/باركود/اسم صنف) → إضافة للسلة. الوحدة المحجوزة لعميل آخر لا تظهر كمتاحة.
2. اختيار العميل: إلزامي لو بالسلة وحدة موتوسيكل (بيانات كاملة: اسم/موبايل/رقم قومي/عنوان)؛ اختياري لبيع إكسسوارات نقدي سريع.
3. الخصومات: على البند أو الفاتورة (نسبة/مبلغ). تجاوز حد الكاشير → نافذة موافقة Manager+ (WF مضمّن: approvals). تعديل سعر وحدة عن السعر المعلن → موافقة حسب المصفوفة.
4. مصاريف فاتورة إن وجدت + حساب الضريبة تلقائيًا حسب الإعداد.
5. شاشة الدفع: توزيع المبلغ على طرق دفع متعددة (كاش + إنستا باي مثلًا)، عرض الباقي للعميل.
6. **الحفظ (معاملة):** `sales_invoices(cash, posted)` + بنود مع `cost_snapshot` + تحديث حالة الوحدات إلى `sold` + `vehicle_movements(sold)` + `stock_movements(sale)` + `vouchers(receipt)` لكل طريقة دفع + `finance_transactions(in)` + `party_transactions` (فاتورة + سداد) + ربط بالوردية + audit.
7. **طباعة فورية:** ريسيت حراري (افتراضي للإكسسوارات) أو فاتورة A4 (افتراضي للموتوسيكلات) — الاختيار بزر واحد.

## WF-04: البيع الآجل

كما WF-03 مع الفروق:
1. العميل إلزامي ببيانات كاملة + الرقم القومي، وتفعيل حد ائتمان اختياري (إعداد).
2. `sale_kind='credit'`، المدفوع عند البيع 0 أو جزئي، والباقي دين على العميل في `party_transactions`.
3. الموافقة: بيع الكاشير الآجل يتطلب موافقة Manager+.
4. السداد لاحقًا: شاشة «تحصيل من عميل» → سند قبض يُوزَّع على أقدم الفواتير المفتوحة (أو فاتورة محددة) + طباعة إيصال.
5. كشف حساب العميل يعرض: فواتير، سدادات، مرتجعات، الرصيد الجاري.

## WF-05: الحجز والعربون

1. من بطاقة وحدة `in_stock`: «حجز» → اختيار العميل + مبلغ العربون + مدة الحجز (افتراضي من الإعدادات، مثلًا 7 أيام).
2. **معاملة:** `reservations(active)` + وحدة → `reserved` + `vehicle_movements(reserved)` + سند قبض عربون + حركة مالية + طباعة **إيصال عربون** يذكر شروط الاسترداد.
3. المآلات:
   - **إتمام البيع:** فتح فاتورة من الحجز → العربون يُخصم من المطلوب → الحجز `converted` والوحدة `sold`.
   - **إلغاء بطلب العميل:** رد العربون (كامل/جزئي حسب سياسة المعرض — Manager+) بسند صرف مرتبط، الحجز `cancelled` والوحدة `in_stock`.
   - **انتهاء المدة:** تنبيه قبل الانتهاء بيوم (إعداد)؛ بعد الانتهاء يظهر للمدير قرار: تمديد / إلغاء مع تحديد مصير العربون (رد / مصادرة كإيراد بسند قبض «مصادرة عربون»). لا إلغاء تلقائي صامت لأمر مالي.

## WF-06: البيع بالتقسيط والتحصيل

**الإنشاء (Manager+):**
1. فاتورة بيع `installment` (نفس خطوات البيع) ثم شاشة «شروط التقسيط»: المقدم، نسبة الفائدة (Flat — افتراض A4)، عدد الشهور، يوم الاستحقاق الثابت (1–28)، تاريخ أول قسط، الضامن (إلزامي حسب الإعداد؛ يُنشأ أو يُختار من `guarantors`).
2. النظام يحسب ويعرض قبل الحفظ: أصل التمويل = الإجمالي − المقدم − قيمة الاستبدال؛ الفائدة = الأصل × النسبة؛ إجمالي المستحق؛ قيمة القسط = إجمالي ÷ الشهور مقربة لأقرب جنيه **والقسط الأخير يمتص فرق التقريب**؛ معاينة الجدول كاملًا.
3. **معاملة:** الفاتورة + `installment_plans(active)` + صفوف `installments(pending)` + قبض المقدم (سند) + بقية قيود WF-03.
4. **المطبوعات:** فاتورة + **عقد تقسيط** (بيانات العميل والضامن والوحدة والشروط) + **جدول أقساط** بعمودَي توقيع.

**التحصيل (Cashier+):**
1. شاشة «تحصيل قسط»: بحث بالعميل/رقم العقد، أو من قائمة «أقساط اليوم».
2. إدخال المبلغ: النظام يوزعه على الأقساط الأقدم فالأحدث (متأخر ثم مستحق)، ويدعم **الجزئي** (القسط يصير `partial`) و**دفعة تغطي عدة أقساط**.
3. **معاملة:** `vouchers(receipt)` + `installment_payments` + تحديث حالات الأقساط + حركة مالية + كشف عميل + لو اكتمل آخر قسط: العقد `completed`. **طباعة إيصال قبض** يبين: المدفوع، الأقساط المغطاة، المتبقي الإجمالي، تاريخ القسط القادم.

**السداد المبكر (Manager+ حسب الحد):** شاشة تعرض المتبقي وتقترح إسقاط فائدة (يدوي/نسبة من فائدة الأقساط المتبقية حسب الإعداد) → موافقة → قبض المبلغ النهائي، الأقساط المتبقية `waived`/`paid` والعقد `early_settled`.

**المتأخرات:** مهمة يومية تُعلّم الأقساط الفائتة وتولد تنبيهات + تقرير متأخرات (عدد أيام التأخير، قيمة، بيانات العميل والضامن) + إمكانية تسجيل ملاحظات متابعة على العقد.

## WF-07: الاستبدال بموتوسيكل مستعمل (Trade-in)

1. داخل فاتورة البيع: «إضافة استبدال» → إدخال بيانات المستعمل الداخل (موديل/لون/سنة/شاسيه/موتور — يُرفض لو الشاسيه لوحدة نشطة بالمخزون) + **سعر التقييم** (Manager+ يعتمده).
2. **معاملة الحفظ:** إنشاء `vehicles` جديدة بحالة `in_stock`، `condition='used'`، `base_cost=سعر التقييم`، مصدرها `tradein` + صف `tradeins` + `vehicle_movements(tradein_received)` + الفاتورة تُخفَّض بـ `tradein_credit` (المطلوب نقدًا = الإجمالي − قيمة التقييم، ولو سالبًا يُرد الفرق للعميل بسند صرف أو يبقى رصيدًا دائنًا).
3. المستعمل الداخل يدخل دورة الحياة الطبيعية: تجهيز (مصاريف على الوحدة) → سعر بيع → بيع، وربحه يُحسب على تكلفة تقييمه + تجهيزه.

## WF-08: المرتجعات

**مرتجع بيع (Manager+):**
1. فتح الفاتورة الأصلية → اختيار البنود المرتجعة (وحدة كاملة أو كميات أصناف) — لا مرتجع بلا فاتورة أصل.
2. تحديد قيمة الرد (افتراضيًا قيمة البند بعد خصوماته) − رسوم إرجاع اختيارية، وطريقة الرد: نقدًا (سند صرف) أو رصيد دائن للعميل.
3. **قيد خاص:** وحدة على عقد تقسيط نشط ⇒ المرتجع يمر بمسار «فسخ عقد» (الوثيقة 09 §E7): تسوية المحصل مقابل قيمة الرد وإغلاق العقد، بموافقة Owner.
4. **معاملة:** `sales_returns` + بنود + الوحدة تعود `in_stock` (مع سؤال: هل تتحول «مستعمل»؟ — قرار مستخدم مسجل) + عكس حركات المخزون + مالية + كشف عميل + audit. **طباعة إشعار مرتجع.**

**مرتجع شراء (Manager+):** بنود من فاتورة شراء أصلية؛ يُرفض إن كانت الوحدة مباعة/محجوزة؛ الوحدة → `returned_to_supplier`؛ الرد نقدًا أو خصمًا من رصيد المورد؛ لو كانت مصاريف موزعة على الوحدة تُعكس قيمتها من التكلفة أو تُسجل كمصروف خسارة (خيار للمستخدم).

## WF-09: الخزنة اليومية والوردية

1. **فتح وردية:** أول عملية كاش تتطلبها. المستخدم يعدّ النقدية الفعلية بالدرج ويدخلها كرصيد افتتاحي (النظام يعرض رصيد إقفال الوردية السابقة للمقارنة، وأي فرق يسجل ملاحظة). `shifts(open)` — وردية واحدة مفتوحة فقط.
2. **أثناء الوردية:** كل سند كاش (قبض/صرف/مصروف) يرتبط بالوردية تلقائيًا. شاشة «ورديتي» تعرض للكاشير: مقبوضات/مصروفات/صافي متوقع بالدرج **بدون** إظهار أرصدة المعرض الأخرى.
3. **قفل الوردية:**
   - النظام يحسب `expected_cash`؛ الكاشير يعد فعليًا ويدخل `counted_cash` (يفضل عدّ فئات العملة في شاشة مساعدة).
   - الفرق: عجز/زيادة → يتطلب اعتماد Manager+ مع سبب، ويُسجل قيد `shift_adjust` مالي حتى تطابق الدفاتر الواقع.
   - **طباعة تقرير Z للوردية:** من فتح/أغلق، المدة، عدد الفواتير، المبيعات بكل طريقة دفع، المقبوضات، المصروفات، المتوقع/المعدود/الفرق.
4. ترحيل النقدية: خيار «توريد للخزنة الرئيسية/البنك» بسند تحويل بين طرق الدفع.
5. **حالات خاصة:** غلق البرنامج والوردية مفتوحة → عند التشغيل التالي تُستأنف نفس الوردية مع تنبيه؛ نسيان القفل ليومين → المدير يملك «قفل إجباري» بتاريخ فعلي مسجل في audit.

## WF-10: إدارة طرق الدفع

1. شاشة طرق الدفع: تفعيل/تعطيل، ترتيب الظهور في شاشة الدفع، رصيد افتتاحي عند أول تشغيل.
2. كل قبض/صرف يحدد طريقة الدفع ⇒ قيد `finance_transactions` فوري. الفاتورة الواحدة تقبل **تقسيم السداد** على أكثر من طريقة.
3. **تحويل بين الطرق** (مثلًا إيداع كاش في البنك): مستند تحويل يولد قيدَي out/in مرتبطين + إيصال.
4. **كشف حساب الطريقة:** فترة + رصيد أول المدة + الحركات (نوع، مرجع، داخل/خارج) + رصيد آخر المدة، مع تصدير وطباعة.
5. **مطابقة دورية:** شاشة «مطابقة رصيد» تقارن رصيد النظام بالرصيد الفعلي (شاشة المحفظة/البنك) وتسجل قيد تسوية بموافقة عند وجود فرق.

## WF-11: النسخ الاحتياطي والاستعادة

موصوف تفصيليًا في الوثيقة 02 §2.4. ملخص تشغيلي:
- تلقائي يومي عند قفل آخر وردية (أو أول تشغيل تالٍ لو الجهاز أُطفئ) + أسبوعي + شهري، مع فحص سلامة قبل الاعتماد وحذف الأقدم حسب سياسة الاحتفاظ.
- زر دائم «نسخة على فلاشة الآن» يكتشف الأقراص القابلة للإزالة ويؤكد النجاح برسالة خضراء + حجم الملف.
- فشل النسخ التلقائي ⇒ تنبيه أحمر مثابر على الشاشة الرئيسية لا يختفي إلا بنجاح نسخة.
- الاستعادة: معالج 4 خطوات (اختيار → تحقق → ملخص وتحذير → نسخة أمان تلقائية ثم استبدال) — Owner فقط.

## WF-12: التقارير

1. كل تقرير: شاشة معايير (فترة، عميل/مورد/طريقة دفع/موديل/مستخدم…) → عرض جدولي مع إجماليات → طباعة A4 / تصدير PDF وExcel(CSV).
2. Dashboard يفتح تلقائيًا بعد الدخول (لمن يملك الصلاحية) ويعرض مؤشرات اليوم لحظيًا (قائمة الوثيقة 08).
3. التقارير تقرأ من نفس القاعدة (WAL يسمح بالقراءة أثناء البيع) وتُبنى على استعلامات مفهرسة، مع «لقطة وقت التوليد» مطبوعة على كل تقرير.
4. تقرير تتبع الوحدة: إدخال شاسيه/موتور/كود ⇒ الجدول الزمني الكامل من `vehicle_movements` + الفواتير والمبالغ والأشخاص.

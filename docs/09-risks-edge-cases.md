# 9. المخاطر والحالات الاستثنائية (Risks & Edge Cases)

## 9.1 مخاطر تقنية وتشغيلية

| # | الخطر | الاحتمال/الأثر | المعالجة المصممة |
|---|---|---|---|
| T1 | انقطاع كهرباء أثناء الحفظ | مرتفع/متوسط | WAL + معاملة ذرّية واحدة لكل عملية: إما تُحفظ كاملة أو لا شيء؛ عند التشغيل التالي `quick_check` + استئناف الوردية المفتوحة |
| T2 | تلف ملف قاعدة البيانات | منخفض/كارثي | فحص سلامة دوري + نسخ يومي مفحوص + إجراء موثق «استعادة آخر نسخة» + عدم وضع الملف على شبكة إطلاقًا |
| T3 | امتلاء القرص | متوسط/مرتفع | فحص المساحة عند بدء التشغيل وقبل كل نسخة (تحذير < 2GB، منع النسخ < 500MB مع تنبيه أحمر) |
| T4 | فلاشة نسخ احتياطي معطوبة | متوسط/متوسط | التحقق بإعادة قراءة checksum بعد النسخ للفلاشة، والنسخ المحلي مستقل عنها |
| T5 | عبث بساعة الجهاز (لتزوير تواريخ) | متوسط/مرتفع | رصد الرجوع للخلف عن آخر حركة ⇒ تحذير + audit؛ التقارير تعتمد التسلسل الزمني للسجل لا الساعة فقط |
| T6 | مضاد فيروسات يعزل التطبيق/يقفل ملف DB | متوسط/متوسط | توقيع الـ Installer، مسارات قياسية (ProgramData)، توثيق استثناء المجلد في دليل التثبيت |
| T7 | ترقية إصدار تفشل في منتصف Migration | منخفض/مرتفع | نسخة `pre_migration` تلقائية قبل أي ترقية مخطط + Migrations داخل معاملة + رفض العمل لو schema_version أحدث من التطبيق |
| T8 | ضياع كلمة مرور الـ Owner | متوسط/مرتفع | أداة استرداد لدى المطور فقط (تتطلب الوصول الفعلي للملف) — تُوثَّق في دليل الصيانة، ولا «باب خلفي» داخل الواجهة |
| T9 | جهاز المعرض يُسرق (بيانات عملاء وأرقام قومية) | منخفض/مرتفع | توصية BitLocker أو SQLCipher (سؤال Q6) + كلمة مرور ويندوز + قفل شاشة بالخمول |
| T10 | المستخدم يفتح نسختين من التطبيق | متوسط/متوسط | قفل تطبيقي (Named Mutex / ملف قفل): نسخة واحدة فقط |

## 9.2 حالات استثنائية في دورة العمل (Edge Cases) وقرار النظام في كل منها

| # | الحالة | قرار النظام |
|---|---|---|
| E1 | بيع وحدة عليها حجز نشط لعميل آخر | ممنوع. تظهر «محجوزة حتى … للعميل …» — الحل: إلغاء الحجز أولًا (بصلاحية وقرار عربون) |
| E2 | عميل الحجز يريد وحدة مختلفة | إلغاء الحجز مع «ترحيل العربون»: سند تحويل داخلي يربط العربون بالحجز/الفاتورة الجديدة بدل الرد والقبض من جديد |
| E3 | شاسيه مكرر عند الشراء (وحدة سبق شراؤها وبيعها ثم عادت للسوق) | الرفض يكون فقط ضد الوحدات **النشطة** (in_stock/reserved/sold غير المرتجعة)؛ الوحدة returned_to_supplier أو المباعة نهائيًا تسمح بإنشاء صف جديد بنفس الشاسيه مع ربط تاريخي يظهر في تقرير التتبع |
| E4 | خطأ إدخال في شاسيه وحدة **مباعة** | تصحيح الحقل متاح لـ Owner فقط بنافذة خاصة بسبب إلزامي + audit بقيمة قبل/بعد + إعادة طباعة الفاتورة والعقد بعلامة «مُصحَّحة» |
| E5 | فاتورة نقدية دفعها العميل ثم تراجع في نفس اللحظة | إلغاء الفاتورة (نفس الوردية، Manager أو موافقة) يولّد سند صرف عكسيًا تلقائيًا بنفس طرق الدفع — لا تعديل صامت |
| E6 | مرتجع جزئي لفاتورة عليها خصم عام | قيمة الرد للبند = صافي البند − نصيبه النسبي من خصم الفاتورة (يحسبه النظام ويعرضه قبل التأكيد) |
| E7 | **مرتجع/فسخ وحدة على عقد تقسيط نشط** | مسار «فسخ عقد» بموافقة Owner: تجميع المحصَّل (مقدم + أقساط) مقابل قيمة استرداد متفق عليها، الفرق سند قبض/صرف، الأقساط المتبقية تُلغى، العقد `cancelled`، الوحدة تعود للمخزون بقرار حالة، وكل ذلك في معاملة واحدة بمحضر مطبوع |
| E8 | عميل يدفع أكثر من قسط اليوم أو مبلغًا أكبر من المستحق | التوزيع التلقائي (B-5): متأخر → مستحق → دفعة مقدمة للتالي؛ الإيصال يوضح التوزيع |
| E9 | يوم استحقاق 29/30/31 | ممنوع من الأساس (يوم 1–28 فقط) — قاعدة V-7 |
| E10 | وفاة/اختفاء عميل تقسيط | العقد يُعلَّم `defaulted` مع ملاحظات؛ النظام يعرض بيانات الضامن؛ التسوية النهائية بمسار فسخ العقد (E7) أو استمرار التحصيل من الضامن — قرار إداري خارج النظام يُسجَّل نتيجةً فقط |
| E11 | استبدال قيمة المستعمل فيه أكبر من الوحدة الجديدة | الفرق سالب ⇒ إما سند صرف فوري للعميل أو رصيد دائن له (خياران في شاشة الاستبدال) |
| E12 | مستعمل داخل بالاستبدال اكتُشف لاحقًا أنه معيب/مسروق | مرتجع خاص: «رد استبدال» — عكس الاستبدال بموافقة Owner (يعيد الدين على العميل أو يقبض الفرق) والوحدة تُعلَّم `returned_to_supplier`-مكافئ (خروج نهائي) بمحضر |
| E13 | فتح وردية بنقدية مختلفة عن إقفال السابقة | مسموح مع تسجيل الفرق كملاحظة تنبيه للمدير (قد يكون المالك سحب نقدية خارج النظام — يُشجَّع تسجيلها سند صرف) |
| E14 | البرنامج أُغلق والوردية مفتوحة، وفُتح في يوم تالٍ | استئناف نفس الوردية مع تنبيه «وردية ممتدة منذ …»؛ Manager+ يمكنه القفل الإجباري بأثر رجعي مسجل |
| E15 | كاشير ينسى تسجيل الخروج ويأتي غيره | قفل الخمول التلقائي + «تبديل مستخدم» من شاشة القفل؛ الوردية تبقى باسم فاتحها والحركات باسم منفذها الفعلي |
| E16 | خصم يجعل الفاتورة صفرًا (هدية/مجاملة) | مسموح بموافقة Owner فقط، وتظهر في تقرير الخصومات كحالة قصوى |
| E17 | بيع بالسالب من صنف كمي (جرد غير دقيق واقعيًا) | افتراضيًا ممنوع؛ إعداد للسماح بتحذير، والفرق يُسوَّى في أقرب جرد |
| E18 | تعديل بيانات عميل (رقم قومي) بعد طباعة عقد | البيانات في العقد لقطة مطبوعة؛ التعديل يسري مستقبلًا فقط، وaudit يحفظ القديم؛ إعادة طباعة العقد تحمل البيانات الجديدة وعلامة إعادة الطباعة |
| E19 | فاتورة معلّقة في POS لم تُستأنف | التعليق في الذاكرة/جدول مؤقت غير مالي؛ عند قفل الوردية يُنبَّه المستخدم وتُحذف المعلقات (لا أثر ماليًا) |
| E20 | استعادة نسخة احتياطية قديمة بالخطأ | الحماية: ملخص النسخة قبل التنفيذ + نسخة PreRestore تلقائية تسمح بالرجوع فورًا |
| E21 | رصيد افتتاحي خاطئ اكتُشف بعد شهور | قيود تسوية معتمدة (manual_adjust) بسبب إلزامي — لا تعديل على الرصيد الافتتاحي نفسه |
| E22 | انقطاع الطباعة (ورق/طابعة مفصولة) بعد حفظ الفاتورة | الحفظ لا يرتبط بالطباعة أبدًا؛ رسالة «حُفظت الفاتورة ولم تُطبع» + زر إعادة طباعة فوري (F12) |

## 9.3 مخاطر نطاق ومتطلبات

| الخطر | التوضيح | التخفيف |
|---|---|---|
| «MVP يشمل كل شيء» | النطاق كبير؛ ضغط الوقت سيغري بالقفز فوق الاختبارات المالية | خطة مراحل (وثيقة 10) بتسليمات داخلية قابلة للاختبار، والاتفاق أن الإطلاق للمعرض يكون بعد اكتمال كل المراحل واختبار قبول |
| غموض قواعد الفائدة والسداد المبكر | افتراضات A4/A5 غير مؤكدة | سؤالا Q2 وQ3 — **يجب حسمهما قبل تنفيذ موديول التقسيط** |
| الفاتورة الضريبية الرسمية | لو المعرض ملزم بالفاتورة الإلكترونية المصرية تتغير المتطلبات جوهريًا | سؤال Q4 قبل تنفيذ الفوترة |
| اعتماد كل شيء على جهاز واحد | عطل الجهاز = توقف المعرض | دليل «جهاز بديل خلال ساعة» + نسخ خارجي أسبوعي إلزامي + اقتراح UPS للجهاز |
